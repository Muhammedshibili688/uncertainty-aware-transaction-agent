# Uncertainty-Aware Transaction Agent: v0.2 Specification

Version: v0.2  
Status: FROZEN AFTER POLICY 2 DEVELOPMENT  
Freeze date: 2026-09-02

## 1. Purpose

v0.2 tests whether the agent can decide what to believe about a verification
result instead of treating every PASS as equally reliable. It is a controlled
extension of v0.1 rather than a replacement fraud-detection system.

## 2. Hidden states

### LEGITIMATE

The account holder authorised the transaction and it is not fraud.

### FRAUDULENT

The account holder did not authorise the transaction or it was later confirmed
as fraud.

The agent never receives the hidden state. It is used only after a final action
to evaluate the result.

## 3. Initial evidence

Policy 2 begins with exactly the same three evidence fields as v0.1:

- `amount_deviation`;
- `device_location_context`;
- `recent_velocity`.

The baseline point mappings remain frozen. Their sum is an integer risk index
from zero to six. It is not a probability.

## 4. Additional evidence

Policy 2 may receive two related values only after selecting
`GET_MORE_EVIDENCE`:

- `step_up_result_if_requested`;
- `verification_independence_if_requested`.

The verification result says what happened during the check. The independence
value says whether the check came through a source meaningfully separate from
the possibly compromised transaction environment.

### Verification results

- `PASS`: the requested check succeeded;
- `FAIL`: the requested check failed;
- `INCONCLUSIVE`: a result was returned but did not resolve the check;
- `UNAVAILABLE`: the check could not be completed.

### Verification independence

- `INDEPENDENT`: the check used a separate trusted channel;
- `SAME_CHANNEL`: the check depended on the same device or session involved in
  the transaction;
- `UNKNOWN`: independence could not be established.

Independence is not the same as correctness. An independent check can still be
wrong, and a same-channel check can still be genuine. It describes evidence
quality rather than the hidden state.

## 5. Actions

- `APPROVE`: allow the transaction and predict LEGITIMATE;
- `GET_MORE_EVIDENCE`: request one verification result and its independence;
- `HUMAN_REVIEW`: defer the final classification to a person;
- `STOP`: prevent the transaction and predict FRAUDULENT.

## 6. Initial decision rule

- score zero to one: APPROVE;
- score two to three: GET_MORE_EVIDENCE;
- score four to six: STOP.

At most one request is permitted.

## 7. Evidence update rule

| Verification result | Independence | Point change |
|---|---|---:|
| PASS | INDEPENDENT | -1 |
| PASS | SAME_CHANNEL | 0 |
| PASS | UNKNOWN | 0 |
| FAIL | any allowed value | +1 |
| INCONCLUSIVE | any allowed value | 0 |
| UNAVAILABLE | any allowed value | 0 |

The final score is restricted to zero through six. The original terminal
thresholds are then used:

- final score zero to one: APPROVE;
- final score two to three: HUMAN_REVIEW;
- final score four to six: STOP.

Policy 2 never requests a second check.

## 8. Evidence-access boundary

Before the initial decision, the agent may see only the three initial evidence
fields. It must not see:

- case ID;
- scenario name or description;
- research category;
- hidden true state;
- raw amount history;
- raw device or location fields;
- raw attempt counts;
- verification result;
- verification independence;
- human-written category reasoning.

The runner may reveal both verification fields only after a request. The hidden
state is read only by the evaluator after the final action.

## 9. Frozen invariants

1. Initial score calculation is identical to the v0.1 baseline.
2. Only scores two and three may request verification.
3. A transaction receives zero or one request.
4. SAME_CHANNEL and UNKNOWN PASS never lower risk.
5. Every final action is terminal.
6. HUMAN_REVIEW remains deferred and is not counted as correct.
7. The agent never receives the hidden true state.
8. Rules may be changed using development findings only.
9. Once evaluation begins, this policy version must not be changed.

## 10. Known limitation

Low-score familiar-context fraud remains indistinguishable when all three
initial evidence categories appear normal. Policy 2 is designed to repair the
misleading-PASS regression introduced by Policy 1, not to claim that missing
features can be recovered through threshold changes.
